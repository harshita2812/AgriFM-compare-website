## Verified remaining gaps

### GAP-01 — No real imagery-to-metrics evaluation path

**Priority:** P0 — core research capability
**Status:** BLOCKED by missing authorized inputs and protocol.

**Expected:** Master Prompt 2 requires the project to make its ML pipeline work and forbids invented results. Master Prompt 4 GAP-02 asks for real inference and metrics, keeping missing assets/compute explicitly blocked.

**Evidence:**

- `ml/README.md:3` says the evaluation pipeline is blocked and not implemented.
- `ml/README.md:5` records that the workspace inventory found no authorized checkpoints, imagery, labels, or split files; required ML libraries and the protocol/runtime were also absent or unverified.
- `apps/api/main.py:93-96` defines the missing-pipeline blocker; `apps/api/main.py:179-194` constructs result records with every metric set to `None`.
- `apps/api/main.py:240-242` labels each run `blocked` and attaches the explicit reason.
- `apps/web/app/App.jsx:270,275,292-298` describes saving setup context, displays unevaluated metrics, and surfaces the blocked status.
- `README.md:60,64-70` states that runs save context only and that the app does not load models, run inference, or calculate ground-truth metrics.
- Current QA evidence: `npm run test:api` passed 9 tests and `npm run test:ui` passed 9 tests (both exit 0). These tests verify truthful blocked behavior; they do not prove inference.

**Impact:** The site cannot answer its central empirical question or produce measured model rankings. This is disclosed rather than hidden.

**What is needed to unblock:** Authorized checkpoint artifacts/revisions and licenses; imagery and ground-truth labels with versions/permissions; task and label schema; held-out geographic split and protocol; preprocessing and metric definitions; and supported compute/runtime requirements.

**Paste-ready fix:** See GAP-01 in [FIX_PROMPTS_2026-11-18.md](FIX_PROMPTS_2026-11-18.md#gap-01--implement-the-real-evaluation-pipeline).

### GAP-02 — Evaluation provenance is declared, not verified against a run

**Priority:** P1 — reproducibility; dependent on GAP-01
**Status:** PARTIAL.

**Expected:** The project should retain reproducibility provenance for reported evaluations without presenting unverified user declarations as evidence.

**Evidence:**

- `apps/api/main.py:123-127` adds a `provenance_json` column to saved runs.
- `apps/api/main.py:197-221` defines typed provenance fields; `apps/api/main.py:224-228` accepts optional declarations with a run request.
- `apps/api/main.py:231-246` deliberately assigns `declared_unverified` or `not_recorded` because inference was not run.
- `apps/web/app/App.jsx:324` displays the unverified/not-recorded status; `README.md:62` says the UI/CSV label declarations unverified.
- `tests/test_api.py` and `tests/e2e/app.spec.js` cover persistence, validation, display, and export (as recorded in `docs/QA_LEDGER.md`).

**Impact:** The infrastructure stores provenance declarations, but cannot associate verified artifact/configuration/runtime evidence with a measured result until an evaluation engine exists. No current saved run has verified evaluation provenance.

**What is needed to close:** GAP-01 inputs and a pipeline that generates provenance from the actual data, checkpoint, split, configuration, code, and runtime used, instead of treating client-supplied values as verified.

**Paste-ready fix:** See GAP-02 in [FIX_PROMPTS_2026-11-18.md](FIX_PROMPTS_2026-11-18.md#gap-02--bind-provenance-to-actual-evaluations).

### GAP-03 — Full dependency audit still reports four high-severity development-tool advisories

**Priority:** P1 — development environment hardening
**Status:** OPEN; production dependency audit is clean.

**Evidence:**

- `package.json:15-24` declares Vite and `@vitejs/plugin-react` as development dependencies; `package.json:10` now binds the compatibility Vite dev server to `127.0.0.1`.
- The prior full audit found 5 high vulnerabilities in the toolchain. Vite was updated to 6.4.6 and `@vitejs/plugin-react` to 4.7.0; this is a compatible pair, and `npm run build:vite` passed after the change.
- The latest `npm audit --json` exited **1** and reported **4 high**, 0 critical, 0 moderate, and 0 low vulnerabilities. They all trace to the same `picomatch` ReDoS advisory (affected range `<=4.0.7`), transitively affecting `fdir`, `tinyglobby`, and Vite. Registry metadata available during this run reports `picomatch` 4.0.7 as current, so no patched picomatch release was available to install.
- `npm audit --omit=dev` exited **0** with **0 vulnerabilities**.
- Downgrading Vite to the audit-suggested 6.2.7 was tested; its build passed, but its audit reported Vite advisories affecting versions through 6.4.3. That downgrade was not retained.

**Impact:** Production dependencies are clean, but the development toolchain remains affected by a high-severity transitive advisory. Loopback-only binding reduces network exposure of the Vite compatibility server but does not remediate the package vulnerability.

**Paste-ready fix:** See GAP-03 in [FIX_PROMPTS_2026-11-18.md](FIX_PROMPTS_2026-11-18.md#gap-03--resolve-or-contain-development-dependency-advisories).
